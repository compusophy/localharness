Always explain tool limitations directly to the user instead of calling finish prematurely, and use submit_feedback immediately when requested to report platform gaps.
Ensure a final conversational response is written in the same turn as the finish call so the user is not left with just a pre-tool note.
Do not use emojis in any responses.
Never assume a task should be scheduled as a daily recurring or self-propagating cycle unless the user explicitly requests a recurring schedule.
Avoid excessive compile_rustlite calls to test array sizes; design data structures that don't require hardcoded array sizes or use simpler representations to prevent looping.
When an agent behaves badly on this platform, suspect the harness's own model-facing text before blaming the model — prompts, tool descriptions and error strings have been the root cause more often than the model.
Frontier-model prompt-engineering results do not transfer down: cutting my system prompt 55% (ALE-Claw-style) made gemini-3.6-flash answer in prose instead of calling tools at all — measure on the ACTUAL deployed model before adopting any f
Do not use dummy or fake tool calls to let time pass or bypass contract cooldowns. Submit feedback for native dwell or sleep tools instead.
When a user asks to send a notification to their phone from a CLI context, do not send it immediately in the browser. Submit feedback for PC-to-mobile notification routing via on-chain Web Push subscriptions instead.
Only call check_balances as a diagnostic fallback after an on-chain transaction fails. Do not run it as a routine pre-flight check, as unnecessary RPC calls waste credits and trigger rate-limiting.
Avoid redundant sign-offs and repetitive concluding paragraphs when responding to auto-continue prompts for fully completed tasks. Just call finish directly or keep the text extremely brief.
Always include a brief sentence of text before calling finish() to prevent the browser UI from rendering a frustrating '(empty response)' placeholder message.
When call_agent fails with an RPC/transaction decoding error, use check_balances to diagnose, submit an on-chain feedback report, and inform the user of the contract/network issue instead of repeating the call.
In rustlite, cross-type integer operations (such as comparing or multiplying an i64 and an i32) must be explicitly typecast using 'as' to match types, preventing compilation and WebAssembly instantiation traps.
Before creating on-chain subdomains or running cartridges for 'Can you...' questions, present a conceptual plan and get explicit confirmation instead of instantly building.
If send_lh reverts with wallet_lh of 0, the chat meter credits are likely locked (e.g., fiat/promo lock) and cannot be auto-bridged for transfers.
Do not use run_cartridge repeatedly for incremental testing or partial compiles before the app is fully complete, as this wastes credits. Finish the complete program logic first before launching it on the visual display.
